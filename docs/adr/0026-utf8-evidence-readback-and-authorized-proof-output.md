# 0026 — UTF-8 evidence readback and an authorized proof-output root in tests

The smoke gate returned exit 1 on source `95932c3d…`. `numerical_tests` failed with **4 failed, 1153 passed, 5 warnings, 23 subtests passed in 928.18 s** over 932.33 s against a 1440 s limit, so it was not a timeout; `real_demo` (48.28 s), `foundation` (61.12 s) and `ui_acceptance` (1.63 s) all returned 0. The previous checkpoint had recorded this gate as pending although the command had already completed and failed. The four failures are `test_lifecycle_workbench.py::test_actual_lifecycle_worker_export_replay_and_checksum`, `::test_lifecycle_cancel_retains_failed_cases_not_success`, `test_proof_worker_isolation.py::test_native_Lean_timeout_and_actual_retry` and `::test_native_missing_executable_is_unknown_and_retryable`.

They have two independent root causes plus one defect the first was hiding, and none of the three is a product-logic regression.

`proof_worker.authorized_output` permits proof output only under `ROOT/artifacts/discovery` or `ROOT/artifacts/test-temp`, forbids reparse points anywhere along the path, and requires the resolved path to stay inside those roots. The smoke gate substitutes `{temp}` from `NAHENG_VALIDATION_TEMP_ROOT` — `<HOST_DATA_ROOT>\…` for this run — and its default is `artifacts/verification/<run>/pytest`. **Neither is an authorized root**, and `test_proof_worker_isolation.py` passed pytest's own `tmp_path` as proof output. That test file was created 2026-10-16 12:38; the only smoke run that ever collected it is the red one at 14:56, while the last green run `smoke-c0aa2b9443` (00:38, 1061 passed) mentions `proof_worker` zero times. The gate has never been green with this file present, under any temporary-root configuration.

The two lifecycle failures are path length. The discriminating experiment is decisive: the same file run with a short basetemp returned **5 passed in 89.74 s, exit 0**, while the long smoke basetemp produced a worker in `state='failed'` and a missing `source_snapshot/artifacts/runs/<run>/manifest.json`. This is the same Windows 260-character boundary already recorded for these tests.

With the output path made legal, the third defect surfaced. Under an authorized basetemp `artifacts/test-temp/pwcheck` the suite returned 1 failed, 3 passed in 704.17 s: `test_native_missing_executable_is_unknown_and_retryable` turned green, and `test_native_Lean_timeout_and_actual_retry` failed with `UnicodeDecodeError: 'gbk' codec can't decode byte 0x92 in position 201`. `proof_worker.py` had four text-I/O sites that declared no encoding — three `read_text()` and one `write_text()` — so reading back the project's own UTF-8 JSON evidence used the Windows locale codec. JSON is UTF-8 by definition, which makes this a portability defect rather than a judgement call: it fails on a Chinese-locale host and passes on a UTF-8 one. `UnicodeDecodeError` subclasses `ValueError`, so inside `prove_batch` it would have been swallowed into `setup_unknown`; that it escaped to the test layer locates the trigger in `register_checked` or in the test's own deliberate-corruption line. Both are the same defect class and both were fixed.

Encoding is now declared `utf-8` at all four sites. The two native tests take a `proof_out` fixture that creates `ROOT/artifacts/test-temp/proof-worker-isolation/<uuid12>` and removes it afterwards, so they carry their own authorized root and no longer depend on where `--basetemp` points; the smoke gate can keep a short D temporary path for the lifecycle tests, and the two constraints stop conflicting. The rejected alternative was to make an authorized root physically short with a junction: `authorized_output` forbids reparse points explicitly, and correctly, since a link would let candidate proof output escape the project-owned tree while still matching the authorized prefix as a string.

Editing `proof_worker.py` invalidated its pin in `configs/discovery/proof-backend.json`, and `verify_backend_inputs` refused to run any proof until it was restored — the intended behaviour. Of 2012 pinned files exactly the 2 edited ones deviated. `tools/repin_proof_backend_encoding_repair_20261016.py` re-pins them only after verifying mechanically that `proof_worker.py` equals the backed-up original with the four declared substitutions applied and nothing else, and that all ten assertion-bearing statements in the test survive after normalizing only the output-path variable name. It writes the full unified diff of both files to an auditable artifact, backs up the manifest with its SHA256, and refuses to run at all if any other pinned file deviates. `verify_backend_inputs()` now returns a pin.

Unchanged: the `authorized_output` guard, every test assertion, every budget, the pinned backend's semantics, and no test was skipped or deselected. `src/naheng/discovery/dataset.py` contains two same-class undeclared `read_text()` calls; they are not on this failure path — `candidate()` executed successfully well before the 704 s failure — so they were deliberately left unmodified to keep the change surface minimal and auditable, and are logged here instead.

Verification was still in flight when this ADR was written: `pytest tests/integration/test_proof_worker_isolation.py tests/integration/test_discovery_loop.py -q --basetemp <HOST_TEMP_ROOT>`, which invokes real Lean and the pinned VM backend. The complete smoke gate has not been re-run, so **smoke is not claimed green** and X00 is not accepted on the strength of this repair.
