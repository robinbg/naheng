# 0027 — Publishing a curated, portable repository instead of the working tree

The work was to be opened for review and contribution. Dumping the working tree would have produced a repository nobody could clone and use, for four concrete reasons that were each verified rather than assumed.

`src/naheng/discovery/proof_worker.py` asserted `boot_path.parent.parent == Path('<HOST_BACKEND_ROOT>')` and `offline_seed.py` hardcoded `<HOST_MAINTENANCE_ROOT>/...` for a wheel and a `.deb`; neither can work on any other machine. `verify_backend_inputs()` pinned 2012 files by SHA256, most of them under `artifacts/handoff/`, and raised a bare `FileNotFoundError` when one was absent — so a fresh clone crashed instead of reporting that the optional backend was missing. `tools/` held 257 scripts, 227 of them one-off session scaffolding, 21 with hardcoded host paths. And 1157 occurrences of the developer's home directory appeared across 175 files, mostly inside evidence receipts.

The isolated proof backend is several GiB of machine-specific QEMU images and an offline Linux rootfs. It cannot be published, and pretending otherwise by leaving hardcoded paths in source is worse than declaring it optional. So `src/naheng/discovery/backend_host.py` now resolves the backend location from `NAHENG_PROOF_BACKEND_ROOT` / `NAHENG_PROOF_MAINTENANCE_ROOT` or from a gitignored `configs/discovery/proof-backend-host.json`, of which a `.example` ships. Absence is an explicit, actionable condition: `verify_backend_inputs()` raises `BackendUnavailable` (a `CandidateError`, so existing handling applies) naming the first absent pinned file, `prove_batch` returns `permission_or_setup_unknown` with `kernel_checked=False`, and `register_checked` still refuses. **An absent backend is never interpreted as a passed proof.** The worker's `PATH` is derived from `SystemRoot` instead of a literal `C:/Windows/System32`.

Of the four tests in `test_proof_worker_isolation.py`, only `test_native_Lean_timeout_and_actual_retry` drives a real proof through the backend; the other three exercise guards that run before any backend is touched. Only that one carries `skipif(not backend_available())` with the install hint as its reason, so a clone reports "3 passed, 1 skipped" rather than silently losing guard coverage. `tests/integration/test_calibration_consumer.py` created its control directory with `mkdir(exist_ok=False)`, which failed on a clone only because the parent did not exist; it now passes `parents=True`, keeping the uniqueness assertion intact.

Evidence receipts record the absolute paths of the machine that produced them, and rewriting them in place would destroy the project's own SHA-linked audit trail. Normalization is therefore applied **to published copies only**: 167 files had the project root, home directory, backend root, maintenance root, delivery root and temporary roots rewritten to `<PROJECT_ROOT>`, `<HOST_USER>`, `<HOST_BACKEND_ROOT>` and similar, with each original's SHA256 recorded in `NORMALIZATION_SHA256.json` so the transform is auditable and reversible. Two test fixtures were normalized in the working tree as well, because they are shipped as source: `tests/fixtures/calibration_builtin/manifest.json` records provenance strings but its SHA256 entries cover the *listed* files, not itself, and `tests/fixtures/evidence_report/legacy-command.json` is only ever compared against values derived from itself. Both were verified by re-running the four affected test files: **90 passed, 11 subtests, exit 0**.

Rules that only match one separator form silently miss the rest, and that happened here: the first normalization pass rewrote 141 files and left 80 occurrences of the account name, because evidence contains forward-slash paths and JSON-escaped paths where every backslash is doubled. Separators are now `[/\\]{1,2}` and a catch-all for the bare account name runs last. Verification is by scan, not by trust: after every generated file is written, the staged tree is re-scanned and the build **fails** on any residual. An earlier revision scanned before writing `BUNDLE_MANIFEST.json` and `EVIDENCE_INDEX.md`, and those two echoed the rules back — including the identifier the rules exist to remove. Derived documents now redact it via `display_rules()`, while the authoritative regular expressions remain in the builder, which is itself an exempt file for exactly that reason. `C:/Windows/System32` was deliberately dropped from the residual pattern: it is identical on every Windows host, carries no personal information, and legitimately appears inside diffs and pre-repair backups. It remains flagged in *source* by `check_portability.py`, which is where hardcoding it actually matters.

Curation is explicit and reviewable rather than implicit. `tools/` ships an allowlist of 33 maintained utilities — those referenced by `configs/gates.yaml`, tests or docs, plus the diagnosis, reproduction and publication tools this README documents — and the 227 excluded one-off scripts stay in the working tree. `START_CODEX.md`, `HANDOFF_CHECK.json` and the 742-line append-only `docs/STATUS.md` do not ship; a concise `docs/STATUS_OVERVIEW.md` is generated from `TASKS.yaml` instead. `configs/discovery/proof-backend-host.json` is excluded by the builder itself, not merely gitignored, so staging matches exactly what a clone receives. `.gitignore` is rewritten for the bundle because the working tree ignores `artifacts/` wholesale while the published tree must track the curated evidence subset.

Two checks run in CI before anything else and both fail the build rather than warn: `check_portability.py` over the published set, and the builder's own citation check, which verifies that every project-relative path mentioned by a bundled Markdown file resolves inside the bundle. Paths that documentation mentions deliberately although they are absent — the `naheng demo` output target, a runtime fixture directory, and one worked example of a genuinely broken citation inside `docs/CLAIMS.md` — must be declared in `EXPECTED_ABSENT` with a reason, so the list cannot be used to wave away a real omission. 121 further unresolvable citations, almost all of them output targets of "next command" lines in historical checkpoints, are published in `EVIDENCE_INDEX.md` rather than hidden.

Verification in the staged tree, with the host config absent to simulate a clone: **1214 tests collected, 0 collection errors** (previously 1177 collected with 2 errors), and `pytest tests/unit tests/security tests/integration/test_proof_worker_isolation.py` reported in `<HOST_TEMP_ROOT>.txt`. Nothing was pushed before those results existed.

This ADR grants no scientific claim. It changes no budget, no guard's intent, no target proposition and no acceptance criterion; `verify --profile release` still returns 2, A03's three arms still await a re-run on repaired source, and the pinned backend manifest was re-pinned only after `tools/repin_proof_backend_portability_20261017.py` mechanically confirmed that exactly three pinned files deviated, that the portability scan was clean, and that all ten assertions in the edited test file survived.

In the published tree: `BUNDLE_MANIFEST.json`, `PORTABILITY_SCAN.json`, `NORMALIZATION_SHA256.json`, `EVIDENCE_INDEX.md`.
