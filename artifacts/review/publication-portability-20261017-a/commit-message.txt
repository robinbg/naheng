把工作树整理成别人能 clone、能跑、能参与的仓库，而不是原样倾倒。

代码与测试
- 移除生产源码中的硬编码本机路径：证明后端位置改由
  naheng.discovery.backend_host 声明（环境变量或 gitignored 配置），
  缺失时给出可操作的 BackendUnavailable，并把结果归为
  setup-unknown（kernel_checked 恒为 False，绝不算通过）。
- 证据回读显式声明 UTF-8：四处未声明编码的文本 I/O 在中文 Windows
  上按 GBK 解码 UTF-8 JSON 而崩溃；JSON 规范即 UTF-8，属可移植性缺陷。
- 证明输出改由测试自带授权根（artifacts/test-temp/proof-worker-isolation），
  不再依赖 --basetemp 落在哪里；smoke 门可继续用短 D 盘临时路径。
- 标定夹具的父目录创建改为 parents=True；两个被冻结登记表
  SHA256 钉住的夹具在工作树内完成路径规范化并经 4 个受影响
  测试文件（90 passed）验证。

发布构建器
- tools/build_publication_bundle.py：策展 tools/（保留 34 个，
  排除 227 个一次性会话脚本）、把证据收据中的本机绝对路径改写为
  <PROJECT_ROOT> 等占位符（工作树原件不改写，原始 SHA256 记录在
  NORMALIZATION_SHA256.json）、扫描全部 Markdown 引用逐条验证、
  最后重扫 staging 确认无残留本机路径。
- tools/check_portability.py：拒绝任何含本机绝对路径的源码进入
  发布集，与构建器共享豁免清单，避免"CI 检查什么"与"发布什么"漂移。
- 数据登记证据链（data-integration-*、artifacts/data/public_independent/**）
  有意不发布：它以 SHA256 钉住且以未再分发的第三方公开数据集收尾，
  发布一半既不可验证，又会暴露产出主机的路径。
  naheng.data.registry_availability 把这一外部数据依赖显式化，
  受影响测试带原因跳过（缺失才跳过；字节不符仍失败）。
- 已发布形式化证据同理：naheng.formal.publication_availability 检查
  活动指针与其引用的编译对象是否存在，5 个绑定验证测试在证据缺失时
  带原因跳过；工作树中同一批测试 59 passed / 0 skipped，真实覆盖保留。
